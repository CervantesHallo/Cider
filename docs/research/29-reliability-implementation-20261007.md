# 评审修正实施与取舍（2026-10-07）

用户已授权现在实施 research/27 的评审发现，A01–A17 已纳入路线图。保持柚子社全系、米哈游三款 Windows 国服本地适配目标，以及 HY1→HY2→HY3→HY4/HY5 的顺序。此轮修复数据保持、安装可信度和启动边界，不以它们代替游戏可玩性。

## 实施范围

- **路径与身份**：Core 的 FileSafety 校验 ID、相对路径与已验证锚点；写入游戏文件拒绝符号链接。瓶子目录排他创建，UUID 避免短随机碰撞；已有瓶子 ID 保持不变。归档先校验路径清单，保留 BSD tar 的安全提取默认，不使用 -P。
- **停止与存储事务**：快照、复制、导出、恢复和设置操作不再吞掉停止失败。FileOperationLock 在 State 中按瓶子/引擎提供同步线程内重入和跨进程锁；配置在锁内重读。快照完成后发布；恢复把前缀、配置和补丁历史共同准备后原子交换。旧目录/旧产物进入废纸篓，失败时仍保留隐藏备份。
- **补丁事务**：安装先暂存并备份全部原文件，再写 journal，逐文件原子替换。失败逆序恢复；中断记录保留，后续安装/撤销可恢复。撤销也有恢复记录。提交序号决定新记录的顺序；旧记录保持时间戳兼容。外部编辑冲突另存，不直接丢弃。未恢复事务阻止整个瓶子启动。旧快照没有补丁历史时，将当前历史隔离保留，不能继续用它撤销旧前缀。
- **副本 Steam 保护**：导入/复制的初始配置就写 cloneSteamBlocked，适用于自定义安装位置；复制身份是边界，不猜测是否曾登录。Run/RunOnce/RunServices 与 Startup 隔离到副本自身的记录。宿主和引擎子进程策略禁止在副本启动 Steam；原前缀不改动。源外部瓶子运行时拒绝导入。
- **下载与诊断**：缓存按固定名称和 SHA-256 消费，目录、链接、特殊文件拒绝，流程内复用也重验；取消检查保留。诊断以 FileHandle 每文件最多读4MiB头尾，不全读历史30.76GB日志；坏编码和坏JSON不原样导出，常见秘密字段、参数和URL查询信息脱敏。
- **数据与 UI**：最终 game 覆盖后校验 profiles；匹配使用安装范围并确定性排序。裸 launcher.exe/HYP 不再无证据自动套米哈游档案；默认两个安装位置及数字版本目录可匹配。UI/catalog/runtime/recipe使用一致的 CompatDB 快照，Data事件刷新；迟到 refresh 不覆盖新结果。后台升级参与 activity 和文件锁，失败可见且不无限自动重试。
- **运行事实与引擎边界**：审计目标在spawn前打开；spawn后写失败仍返回已启动的 SessionHandle，并向UI/CLI提示。配置无法读取时不启动，不能取消副本保护。引擎替换检查server以及启动窗口/孤儿进程；目录枚举失败不会当作空集合。未知 loader 导入不执行 --version，仅以包名取得非可信版本提示。
- **证据维护**：配方实际采用的 Highball0012/0013 与最初提案分开记录；KernelFidelity 的不可达注释绑定当前审计实现，不宣称所有未来架构永久不可达。没有把矩阵标签改成已实现内核 API。

|---|---|---|---|---|
| 原子交换目录/文件，保留旧产物 | 失败前不撤掉旧引擎/备份；恢复配置和前缀一致 | APFS克隆目录/原文件备份增加元数据与磁盘占用；隐藏备份须可查 | 源码状态机与编译；仍需复制/磁盘/提交故障注入 | 旧产物/快照可恢复，代码独立Git提交 |
| 外部 State 锁，跨入口操作串行 | GUI/CLI不能在停止、复制、保存间穿插启动 | 操作可等待或明确超时；不提供对恶意同用户原生进程的隔离 | 统一锁顺序：瓶子→引擎，瓶子→补丁；并发验收仍待完成 | 先停止进程，再恢复旧代码/产物 |

## 能力绑定的边界

EnginePolicy 的有限清单绑定当前 r1/r2 原生 ntdll、实际 loader、bootstrap 和 wineserver 文件哈希。它用于既定构建的启动能力判定，不能视为整个引擎来源认证、文件系统隔离或对恶意宿主代码的证明。完整签名通道仍属原计划；未知原生链不能从自称 manifest 获得执行许可。当前三款游戏的固定门禁保持，HY3 的版本环境许可闭环没有因此完成。
