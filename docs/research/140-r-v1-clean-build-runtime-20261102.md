## 真实HYP首轮失败及对照边界

原固定135份1.18 vendor payload在新整包上，20／55／80秒只观察到两个
空标题500×500初始化窗口和黑图，没有主窗。保留失败和CEF的commit-hung日志，
不因已有context或截图生成就算渲染通过。

同一新资料目录另建空参考瓶、使用137旧组件预览及同一payload，75秒
得到完整1280×720主界面和1.19更新提示；截图已实际查看，未点击更新或协议。
新整包仅按瓶子切到server同步也出现完整界面，之后恢复msync。
随后旧core组、旧PE ntdll组的临时对照均出现主窗并完整回退。

但全新原整包／PE／msync恢复后同样成功，新空瓶FreshClean2首次启动也成功。
因此这些正向替换受持久appdata／缓存／时序混杂，不能据此认定DLL、编译器
或同步算法根因，不能用旧DLL／server回退作为修复。最初失败仍未闭合。

限定只读对照还确认：旧基底重点PE来自本地Wine11.18，并非所查CX遗漏；
旧／新config.h相同，native ntdll 25个对象中24个text相同，server 46个中45个
text相同；PE sync.c规范化预处理输出一致，关键syscall stub／RVA一致。
这些是范围与排除性证据，原生sample反复出现的Rosetta dispatcher帧不证明递归。
独立子代理仅写组件比较报告，父代理自行执行现场取证／对照并复核。
