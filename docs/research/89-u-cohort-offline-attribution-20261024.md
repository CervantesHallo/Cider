日期：2026-10-24。承接 85，未重新运行基准，没有改变原门槛、重加权、排除或改写回执。

90 个原始回执的 SHA256 全部核对，720 个 batch 和 3360 个 worker 区间完整保留。子代理提供的纯标准库分析脚本由父代理检查并再次执行，输出摘要完全相同；完整脚本、全体行及派生表位于 `out/sync-user-bench-20261024/offline-attribution-v1/`。可提交的复现入口为 `scripts/analyze-user-cohort.py --input out/sync-user-bench-20261024 --out <新目录>`，父代理实际执行后核对全部派生数据相同（仅脚本自身摘要不同）；摘要账本与 15 组完整派生表见 `evidence/u-cohort-offline-attribution-20261024.json`。

原结论仍为 **8/15 超出 ±3%，7/15 在范围内**。其中 10/15 单元的三次配对成本差异出现过正负方向变化；同模式的三次运行也有明显跨度。这是已有数据中的变化，不能证明其原因是宿主噪声，也不能证明 msync 没有间接影响。

现有顺序每组是 S/M、M/S、S/M；反向顺序只有一次，工作负载按固定时间块进行。顺序、时间、负载历史和后端效应不能由这三对独立分解。四个 batch 也不是四份独立进程重复样本。

QPC 只提供墙钟区间，当前缺少相同 worker 区间内经验证的原生线程 CPU 时间，以及运行、就绪／离 CPU、阻塞的执行状态。完成较早的线程在自身计时外自旋，可能与尚未完成的线程重叠；区间尾差仅给出这种重叠机会，不证明实际自旋驻留或因果干扰。

下一项计量实现须先验证来源。不能直接采用可能回退为进程 CPU 的 Wine GetThreadTimes，不能将 Mach 端口名字当作全局线程 ID，也不能通过改 QoS／亲和性或放宽门槛制造通过。当前不据此修改同步内核或默认采用候选。
