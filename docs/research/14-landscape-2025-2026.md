## 摘要

- **平台时钟已经走到终点前一年。** macOS 27 Golden Gate 于 **2026-09-14** 发布，是**第一个只支持 Apple silicon 的 macOS** [5]。
  - Apple 支持文档 102527（2026-09-21 更新）：Rosetta 在 macOS 27 及更早版本上可用；从 macOS 28（预计 2027 年秋）起，只为 “certain older, unmaintained games that rely on Intel-based frameworks” 保留 [2]。
  - 2026-09-01 的开发者新闻：macOS 27 是最后一个支持 Rosetta 的版本，老游戏例外会继续保留，但文中没有点名 macOS 28 [1]。
  - Apple 在 2026-09-09 发的另一篇开发者新闻写成“macOS 26 是最后一版”，与上面两处矛盾，至今没有更正 [3][75]。规划以 102527 和 2026-09-01 那篇为准。
  - **Cider 的 x86_64 Wine + Rosetta 引擎，可靠有效期只到 2027 年秋。** [高]
- **CodeWeavers 已先行一步。**
  - CrossOver 27 计划 2027 年初发布，只支持 Apple silicon 和 macOS 14 及以上，32 位 bottle 将无法使用 [15][16]。
  - 2026-07-31 的 Mac 版 ARM64 Preview **不含 D3DMetal/DX12**，多数启动器不可用，旧 bottle 也不能转换 [16][17]。
  - 有两点**未经一手核实**：它用的是 CodeWeavers 自行移植到 macOS 的 **FEX**；ARM64 部分要求 macOS 26.5 及以上。这两点只见于第三方的 Highball #6 [38] 和搜索引擎对 CodeWeavers 博文的摘要。博文本身抓取返回 403，AppleInsider 的报道也没有提到 [16]。[低/中]
  - 上游 FEX 目前**没有 Darwin 宿主支持**：CMake 只接受 Linux 或 Windows（MinGW）宿主 [76][77]。
  - PortJump（CodeWeavers 的移植服务）计划在 2026 年底前推出基于 ARM64 的 beta [18]。

  [中]
- **ARM64 时代最大的缺口是 DX12。**
  - 目前发行的 D3DMetal（GPTK 3，以及 CrossOver 26 内置的 D3DMetal 3.0）**只有 x86_64 版本**。在 Apple silicon 上，整个进程必须跑在 Rosetta 2 下，无法加载进原生 arm64 或 FEX 的 Wine 进程 [39][40][41]。
  - **GPTK 4 / D3DMetal 4（WWDC26）有没有 arm64 版本，没有任何能查到的来源说明** [8][9]。
  - 按 UTM 对其许可证的转述，D3DMetal 只能用于 “developing, testing, or evaluating video games”，只能非商业分发，因此不能随 UTM 打包 [41]。

  [高：仅指已发行版本；GPTK 4 的架构未知]
- **开源翻译层在 2025–2026 年进步很快**：
  - Wine 11.0（2026-01-13）完成了新 WoW64 [21]。
  - DXMT 从 v0.70 到 v0.80 用 Metal mesh shader 重写了曲面细分，加入 D3DKMT 共享资源，并实验性支持 Intel。**v0.80（2026-04-23）是最后一个 MIT 许可版本，之后改为 LGPL** [22][23]。
  - KosmicKrisp 于 2026-09 通过 Vulkan 1.4 一致性认证 [25]；MoltenVK 1.4.2 于 2026-07-20 发布 [24]。

  [高]
- **Valve 不做 macOS，但在资助 FEX。**
  - Proton 11.0-1（2026-07-07）rebase 到 Wine 11.0，并为 ARM64EC 构建加入 FEX-2605；11.0-2（2026-08-21）升级到 FEX-2607 [28]。
  - ARM 头显 Steam Frame（Snapdragon 8 Gen 3）于 2026-09 中旬开卖，Valve 称 FEX 的开销约 10–20% [30][31]。
  - Steam 的 Mac 客户端已经是原生 arm64 [32]。

  [中/高]
- **免费前端的格局已经重新洗牌。**
  - Whisky 于 2025-05 归档 [33][34]。
  - 新项目 **Highball**（2026-08-23 创建，GPL-3.0，兼容性数据库用 CC0，约 1.1k star）的定位几乎和 Cider 完全重合。它的 Wine 11 引擎基于 CodeWeavers 的 CrossOver 26.3 源码树构建 [37]。
  - 此外还有 frankea/Whisky [35]、Sikarugir [36]，以及 NotProton（在 macOS 上启用 Steam Play）[39]。

  [高]
- **虚拟机只能兜底，替代不了兼容层。**
  - Parallels：在 Apple silicon 上的 3D 加速只到 **DirectX 11.1 / OpenGL 4.3** [43]。
  - VMware Fusion 25H2（2025-10-14）：个人、教育和商业使用都免费 [46]。Apple silicon 上的 Windows 11 客户机从 Fusion 13.5 起就支持 DX11，25H2 仍然支持 [83]。25H2 的发布说明本身没有提 3D。
  - UTM 5.0.5 beta（2026-09-02）：加入实验性的 Triton 驱动（后端为 Neptune/virglrenderer）。
    - Triton 博客列出的宿主机 DX11 后端有 DXMT 和 D3DMetal 两个 [41]。
    - macOS 上，DX12 “在 D3DMetal 可用时”支持；D3DMetal 不能随 UTM 分发，需要用户自备 GPTK [41][42]。
    - **驱动仍是实验性的，可能导致系统不稳定** [42]。
  - Windows on Arm 的 Prism 从 2025-10 起支持 AVX/AVX2 [47]。

  [高]
- **云游戏已经成熟，但有时长上限，也有地区限制。** GeForce NOW 已升级到 Blackwell（RTX 5080 级），Ultimate 档 $19.99/月，2026-01 起每月 100 小时上限 [50][51]。Xbox Cloud Gaming 于 2025-10 结束 beta，Game Pass Ultimate 涨到约 $30/月 [52]。[中]
- **原生移植明显增多。** 代表作有：
  - AC Shadows（2025-03-20，与主机同日登陆 Mac）[53]、Cyberpunk 2077（2025-07-17）[54]。
  - Crimson Desert（2026-03-19，首发即上 Mac）[56]。
  - 网易《燕云十六声》Mac 原生版（2026-08-19 先行体验）[57]。

  Apple 在 WWDC26 推出了 GPTK 4 的 agent skills 和 Steam Asset Converter，把“原生移植”做成了流水线 [6][8]。**推断：头部 AAA 越来越多走原生路线，Cider 的价值会转向长尾游戏、老游戏、未移植的热门游戏和非游戏 Windows 应用。**
- **硬件方面：**
  - M3 起有硬件光追、mesh shading 和 Dynamic Caching [60]。
  - M5（2025-10）每个 GPU 核心都带 Neural Accelerator [61]；M5 Pro/Max 于 2026-03 发布 [62]；**M6 和 M5 Ultra 于 2026-08-25 发布** [63]。
  - **MacBook Neo** 于 2026-03-04 发布，首发起价 $599，用 A18 Pro，固定 8 GB 内存 [65][66][81]。2026-06-25 起因全球内存短缺涨价到 $699/$799，$599 只保留为教育价 [66][82]。
  - Steam 2026-08 的 Mac 用户中，**8 GB 内存占 29.44%**，16 GB 占 43.41% [67]。
- **对 Cider 的核心建议：**
  - 只支持 Apple silicon；最低 macOS 15，macOS 14 尽力支持；推荐 16 GB，8 GB 作为“轻量档”。
  - ARM64 引擎**暂以 macOS 26.5+ 为目标**，必须在 **2027-06（WWDC27 / macOS 28 beta）前**可用。26.5 这个下限只来自对 CrossOver Preview 的第三方转述，需要在 Engine A 原型阶段实测出真正的最低版本。
  - 差异化方向：完全开源的引擎、按应用配置、与 Highball 共用开放兼容库（不重复造轮子）、中文市场、非游戏类 Windows 应用。

#### 1.2 Apple：WWDC25 / WWDC26、Rosetta 退场与 macOS 27

**WWDC25（2025-06）→ macOS 26 Tahoe**

- **Metal 4**：
  - 硬件覆盖 **M1 及以后的 Mac**，以及 A14 及以后的芯片 [10]；
  - 在 MetalFX 中加入 **Frame Interpolation** 和 **Denoising** [12]；
  - 另有可定制的 Metal Performance HUD [12]。
- **Apple Games app**：汇总“all the games they have on Mac”[11]。
- **Game Overlay** 和游戏用的 Low Power Mode [12]。
- **Game Mode**：
  - 全屏时自动触发；
  - 给游戏最高的 CPU/GPU 优先级，并把蓝牙采样率翻倍；
  - macOS 14 起支持，在 Tahoe 上用 Game Overlay（Command-Esc）开关 [13]。
- **对 Cider 的直接含义**：
  - 游戏窗口要支持原生全屏，Game Mode 才会触发。
  - **推断**：如果给每个游戏生成 `.app` 包装，并在 `Info.plist` 里声明 `LSApplicationCategoryType = public.app-category.games`，这些游戏很可能会出现在 Games app 的资料库里，并被系统当作游戏处理。这一点需要在 macOS 26/27 上实测。

**WWDC26（2026-06-08）→ macOS 27 Golden Gate**

- **GPTK 4**：
  - 评估环境升级到 Metal 4，支持 DX12、sparse、HDR、超分、降噪和插帧 [9]；
  - 新的 GitHub 仓库 `apple/game-porting-toolkit`（Apache-2.0），提供 Metal/MetalFX 专家 skills 和移植流程 skills；
  - 该仓库**要求 macOS 27 和 Xcode 27**，并提供命令行的 Metal 调试工具 `gpucapture`/`gpudebug` [8]。
  - 官方 GPTK 页面和 `apple/game-porting-toolkit` 的 README **都没有说明 D3DMetal 4 的 CPU 架构**，也就是有没有 arm64 版本 [8][9]。
  - 媒体实测（AppleInsider，2026-06-17）[73]：D3DMetal 4 把 DX12 转成 Metal 4。GPTK 4 相对 GPTK 3 的提升因游戏和机型而不同：
    - Red Dead Redemption 2（MacBook Neo）：平均多 7 fps，约 25%；
    - Subnautica 2（Mac mini M4，16 GB）：约 6%；
    - Cyberpunk 2077（M3 Max，48 GB，40 核 GPU）：生成帧数多约 10%。

    旧版这里写的 “Black Myth: Wukong 在 M3 Max 上从 60 fps 提升到 80 fps”，**在该文中不存在，已删除**。[中：机型与数字的对应关系来自抓取工具转述]
- **Metal 4.1**：
  - MetalFX 的时域超分器重新设计，在 **M5 Pro/Max** 上会用到 Neural Engine 和 Neural Accelerators；
  - 支持子矩形动态分辨率、运动矢量输入和畸变场 [7]。
- **Steam Asset Converter**：把 Steam depot 转成 Managed Background Assets 清单，**方便 Steam 游戏上架 App Store** [6]。
- **推断：Apple 的战略很明确，就是降低原生移植的成本，而不是扶持运行时翻译。** GPTK 从头到尾都叫 “evaluation environment”。

**Rosetta 退场：细节与矛盾** [1][2][3][4]

- Apple Developer News（2026-09-01）：
  - macOS 26.4 起，启动 Rosetta 应用时可能弹出提示；
  - **macOS 27 是 Rosetta 通用支持的最后一个版本**；
  - 之后 “Rosetta functionality for older, unmaintained gaming titles that rely on Intel-based frameworks will continue to be supported” [1]。
  - 这篇**没有点名 macOS 28**，并说这个计划在“去年的 WWDC”（WWDC25）就已宣布 [1]。
- Apple Support 102527（2026-09-21 更新）写的是：“Rosetta is available for any Mac with Apple silicon using macOS 27 or earlier”；从 macOS 28 起只保留给 “certain older, unmaintained games” [2]。“certain older, unmaintained games” 这个说法只出现在这一页。
- MacObserver 发现（2026-09-12）：Apple 在 2026-09-09 发了另一篇开发者新闻（id k1mtkt1k，“App Store submissions now open…”），写成 “macOS 26 is the final release supporting Intel Mac computers and Rosetta”，与前两处矛盾 [3][75]。
  - 核查确认这篇新闻确实存在，Apple 至今没有更正。
  - 推断：它大概率是 App Store 提交公告里的措辞疏忽，把“Intel Mac 支持”和“Rosetta”混在了一起，而不是新政策。
  - **规划以 102527（2026-09-21 更新）和 2026-09-01 那篇为准。**
- 在 macOS 27 上：Intel 应用的 Get Info 窗口和启动时会提示 “will not open in macOS 28”，安装 Rosetta 时也有同样的警告 [4]。
- **关键未知**：“老游戏例外”的判定机制（白名单？框架依赖？bundle ID？）没有公开，核查也没有找到任何来源说明。**Wine 进程能不能落入这个例外，目前没有任何依据，不能指望。**

**macOS 27 的其他事实**

- 支持所有 Apple silicon Mac，包括 M1 和 MacBook Neo；**不支持任何 Intel Mac**；**Tahoe 是 Intel Mac 能装的最后一个版本** [5]。
- 采用率：Steam 2026-08 的 Mac 调查里，macOS 27.0.0（当时还是 beta）已占 3.86% [67]。

#### 1.5 Valve：Steam Frame / Steam Machine / Proton ARM64 / 与 macOS 的关系

- **Proton 11**（2026-07-07）：rebase 到 Wine 11.0，DXVK 升到 v2.7.1-467，“Added FEX-2605 for ARM64EC builds”；11.0-2（2026-08-21）升到 FEX-2607 和 vkd3d-proton v3.0a-252 [28][78][79]。**Valve 已经把 “Wine ARM64EC + FEX” 做成了官方产品形态。**
- **Steam Frame**（ARM 头显，Snapdragon 8 Gen 3，16 GB）：Windows 游戏走 Proton + FEX，Android 应用走 Lepton。Valve 工程师称 FEX 的开销约 10–20% [31]。开卖日期各来源不一致，在 2026-09-14 到 09-18 之间 [30]。[中]
- **Steam Machine**（x86，Zen 4 + RDNA 3）：2026-06-25 前后开放购买，$1,049 起 [29]。与 Mac 无关。
- **与 macOS 的关系**：
  - Valve 没有公开任何 macOS 版 Proton 的计划。
  - Mac 版 Steam 客户端已转为原生 arm64：2025-10 beta 的 bootstrapper 改成 universal；到 2026-03，已有用户在 M5 上不装 Rosetta 就能用 Steam [32]。[中]
  - 社区项目 NotProton 会启用 macOS Steam 里休眠的 Steam Play，同时提供 Rosetta（x86_64）构建和 FEX（arm64）构建。FEX 构建依赖 “CrossOver Preview 2026082” [39]。它的 PR #4（2026-09-25）写明：D3DMetal 只有 x86_64 版本，FEX 构建的 `cxcompatdb` 会判定它不可用，然后**静默回落**到其他后端 [39]。
- **推断**：Valve 在 Linux 上推动 FEX 成熟，对 Cider 是正外部性：FEX 的 JIT 质量、ARM64EC 适配和游戏兼容修复都能复用。但 macOS 特有的部分，包括 Mach-O、4K 页、TSO、W^X/JIT 权限，Valve 不会替 Cider 做（详见 06 号报告）。

### 2. 替代方案：虚拟机、云游戏、原生移植

#### 2.1 虚拟机（Windows 11 on ARM + Prism）

**结论**：
- VM 的优势在这些场景：①需要真实 Windows 内核或驱动的软件，例如 USB 加密狗、网银 U 盾、打印或扫描驱动、企业 VPN；②依赖 .NET、Office 插件等“完整 Windows 语义”的办公软件；③少数只支持 WoA 反作弊的游戏。
- 兼容层的优势在这些场景：DX12 AAA、GPU 性能、内存占用、与 macOS 窗口和文件的集成、启动速度。
- 媒体评测普遍说 CrossOver 比 Parallels 快 30–50%（二手，[72]，低置信度）。
- **UTM 的 Triton/Neptune 是新变量**：它说明“VM + 宿主机 Metal 翻译”技术上可行，而且用的正是 Cider 也会用的 DXMT。推断：长期看，Cider 可以考虑一个“开源 VM 后端”作为兜底，与 UTM 合作而不是自己重做。

#### 2.2 云游戏

- **GeForce NOW**：
  - 2025 年起升级到 Blackwell（RTX 5080 级），Ultimate 档 $19.99/月，最高 5K 120 fps；有 Mac 客户端 [50]。
  - **从 2026-01-01 起所有付费档每月 100 小时**，可结转 15 小时，Ultimate 额外 15 小时售价 $5.99 [51]。
  - 只能玩“已上架 GFN 且你拥有”的游戏；不支持 mod；不能离线；对网络要求高。
- **Xbox Cloud Gaming**：2025-10 结束 beta，支持 1440p（部分游戏和设备），码率从 10 Mbps 升到 27 Mbps；Game Pass Ultimate 涨约 50% 到约 $30/月 [52]。Mac 上通过浏览器使用。
- **中国大陆**：GeForce NOW 和 Xbox Cloud 都没有官方服务（**推断，未在本次调研中核实**）。国内有各自的云游戏平台，但覆盖的游戏库不同。
- **结论**：云游戏是 Cider 的“补充”，不是威胁。有反作弊的多人游戏（Cider 无解）可以在 UI 里引导用户去云端或原生版本。

#### 3.2 安装基数（Steam 2026-08 Mac 调查，作为“游戏用户”的代理指标）[67]

- **芯片**：M4 18.24%、M1 14.99%、M2 10.72%、M5 9.85%、M3 5.94%、M4 Pro 4.93%；Intel（GenuineIntel）11.08%；VirtualApple（x86 版 Steam 跑在 Rosetta 下）2.79%。[中：抓取工具转述，分项口径可能混合]
- **内存**：16 GB 43.41%、**8 GB 29.44%**、24 GB 10.74%。
- **系统**：macOS 26.5.2 占 30.60%；26.6.x 合计约 15.7%；27.0.0 占 3.86%。TelemetryDeck 2026-08-31 的数据同样显示 26.x 占绝对多数（26.6 占 54%，26.5 占 25%）[68]。
- **推断**：
  1. 仍有约 11% 的 Intel Mac 用户，但 CrossOver 27 和 macOS 27 都已放弃 Intel，Cider 没必要支持。
  2. 在 Apple silicon 用户中，M1/M2（没有硬件光追）约占四成，仍是主流。
  3. 8 GB 用户约占三成，再加上 MacBook Neo 带来的新低端用户，**Cider 必须能在 8 GB 上跑中低负载游戏和应用**。
     - Neo 的入门价在 2026-06-25 已涨到 $699，但教育价仍是 $599 [82]，学生群体的 8 GB 基数会继续扩大。
     - 传闻第二代 Neo 升到 12 GB [82]，但这只是传闻，未证实，不改变“8 GB 轻量档”的规划。

| 档位 | 建议 | 理由 |
|---|---|---|
| CPU 架构 | **只支持 Apple silicon**（M1+，含 A18 Pro 的 MacBook Neo） | macOS 27 已不支持 Intel [5]；CrossOver 27 同样只支持 Apple silicon [15] |
| 最低 macOS（x86_64/Rosetta 引擎） | **macOS 15 Sequoia**（硬性）；macOS 14 “尽力支持”，不纳入 CI | Rosetta 从 macOS 15 起才支持 AVX/AVX2（06 号报告）；GPTK 3 beta 要求 macOS 15（05 号报告）；Steam 和 TelemetryDeck 数据显示 14 的份额很小。CrossOver 27 支持 14+，这是一个可以接受的小差距 |
| ARM64/FEX 引擎 | **暂定 macOS 26.5+（待实测）** | 26.5 这个数字只来自对 CrossOver ARM64 Preview 的第三方转述 [38]，一手来源未核实，AppleInsider 也没有提到 [16]；06 号报告推断与 4K 页、TSO 相关的内核路径有关。Engine A 原型阶段要在 26.x 各版本上实测，定出真正的下限，下限有可能更低。开发机是 26.5，不影响起步 |
| KosmicKrisp / Metal 4 编码 / MetalFX 插帧 | macOS 26+ | 见 05 号报告；`MTLFXFrameInterpolator` 从 macOS 26 起可用 |
| 主测试矩阵 | macOS 26.x、27.x，2027-06 起加上 28 beta | 用户分布 [67][68] |
| 内存 | 推荐 16 GB；**8 GB 作为“轻量档”**（默认更小的 shader cache 和 JIT cache，UI 提示 AAA 游戏不适用） | 8 GB 占 29.44% [67]；原生版 Cyberpunk 都要求 16 GB [54] |
| GPU 特性 | M3+ 开启 DXR/mesh 相关路径；M5 Pro/Max 开启神经网络超分 | [60][7] |

### 4. 竞争定位

#### 4.1 CrossOver 的强项与弱项

| 强项 | 弱项 / 机会 |
|---|---|
| 与 Apple 有合作渠道，**唯一能合法内置 D3DMetal 的商业产品**（01 号报告） | 闭源 GUI、闭源兼容库、闭源逐游戏配置；EULA 禁止逆向 |
| 雇用了 Wine 在 Mac 方向的核心开发者，同时做上游 | 启动器一更新就坏，要等点版本修复（01 号报告） |
| Apple silicon 原生的 ARM64 Preview 已经发布，时间上领先 [16]（用的是 FEX 这一点只见第三方转述 [38]） | ARM64 Preview 没有 DX12，多数启动器不可用；旧 bottle 不能迁移，**2027 年初会有一轮迁移阵痛** [16] |
| 覆盖办公软件和游戏，有企业与 PortJump 业务 [18] | 按 bottle 配置，诊断能力弱（Metal HUD 等没有 GUI 入口），用户体验偏旧（01 号报告） |
| 中国区有代理，¥199 永久授权，还捆绑加速器 [20] | 收费；社区贡献渠道少 |

#### 4.2 VM 与兼容层各自的适用场景

| 场景 | 更适合 | 说明 |
|---|---|---|
| DX12 AAA 单机游戏 | 兼容层（D3DMetal） | Parallels 不支持 DX12 [43] |
| DX9–11 游戏 | 兼容层 | 性能和内存都更好 |
| 内核级反作弊（Vanguard、Ricochet、ACE 等） | 两者都不行，改用云或原生 | 08 号报告 [48][49] |
| EAC/BattlEye（开发者已为 ARM 开启） | VM 有少量机会 | 截至 2026 年中，WoA 上 EAC 只确认 Fortnite 可用 [49] |
| 需要内核或驱动的软件（U 盾、加密狗、专用硬件） | VM | Wine 没有 ring-0 |
| 日常 Windows 应用（中文办公、ERP、行业工具） | 两者皆可；兼容层集成更好，VM 兼容性更稳 | Cider 可以做“应用配方” |
| 8 GB 机器 | 兼容层 | VM 要额外承担整个 Windows 的开销 |

#### 4.3 Cider 的差异化机会

1. **完全开源的引擎和配方**：所有补丁公开，吸取 Whisky 的教训，回馈上游 [34]。Highball 已经在这条路上 [37]，Cider 应当**合作而非复制**：采用或兼容 Highball 的 CC0 配方格式和兼容库，共享数据，把力气花在它没做的地方。
2. **ARM64 引擎的开源实现**：据第三方转述，CodeWeavers 用的是自行移植到 macOS 的 FEX [38]，一手来源未核实；上游 FEX 本身没有 Darwin 宿主 [76][77]。这个移植是否开源仍是未知数（FEX 是 MIT 许可，没有开源义务）。**谁先做出开源的 macOS FEX 后端，谁就掌握 2027 年之后免费方案的命脉。** 这是 Cider 最有价值、也最难的差异点。
3. **按应用配置和自动选择后端**，配合诊断 UX：一键开关 Metal HUD、日志打包、后端 A/B 对比。
4. **中文市场**：
   - 全中文 UI 和文档；
   - 国内镜像分发 Wine 和依赖组件（CDN）；
   - 适配国内启动器和平台（WeGame、网易、米哈游启动器等，需要逐个验证）；
   - CJK 字体和输入法（09 号报告）；
   - 常用国产 Windows 软件配方；
   - 标出“该游戏已有 Mac 原生版”（例如燕云十六声 [57]）。
   - CrossOver 中国区价格 ¥199 [20]，对价格敏感的学生群体来说，免费本身就是卖点。
5. **系统集成**：为每个游戏生成 `.app` 包装，让游戏进入 Games app 并触发 Game Mode [11][13]；接入 MetalFX 插帧（DXMT、nvngx shim）；支持原生全屏。
6. **Steam 集成**：借鉴 NotProton 和 macos-steam 的思路，在 macOS 版 Steam 里直接启动 Windows 游戏 [39]。
7. **路由而非硬扛**：UI 里标注“原生版 / GeForce NOW / 需要 VM / 反作弊不可行”，建立“什么工具最合适”的信任。

## 对 Cider 的启示与建议（按优先级）

**P0：决定生死**

1. **平台基线**：只支持 Apple silicon；最低 macOS 15（14 尽力支持）；主测 26.x 和 27.x；推荐 16 GB，8 GB 走轻量档；不做 Intel，不做 32 位 bottle（统一用新 WoW64）。
2. **双引擎和硬性时间表**：
   - Engine R（x86_64 Wine + Rosetta）马上作为 MVP；
   - Engine A（ARM64 Wine + ARM64EC + FEX）要在 **2027-06 WWDC27 之前**，在 macOS 26.5+ 上达到“DX11 游戏可用”。26.5 是暂定下限，依据只有第三方转述，原型阶段要实测确定（见 §3.3）；
   - 2027 秋 macOS 28 发布时，Engine A 成为默认。
   - 上游 FEX 没有 Darwin 宿主 [76][77]，Engine A 的 FEX 需要 Cider 自己做 macOS 宿主移植，或者等 CodeWeavers 公开源码。
   - 盯紧 CrossOver 27 的源码发布（预计 2027 年初），Wine ARM64 部分是 LGPL，可以直接吸收 [38]。
3. **DX12 战略要接受现实**：
   - 短期让用户从 Apple 导入 GPTK 的 D3DMetal，**不内置** [41]。目前发行的版本只有 x86_64，只能用于 Engine R。
   - 导入时用 `lipo -archs` 检查 `D3DMetal.framework` 的架构。GPTK 4 / D3DMetal 4 有没有 arm64 切片目前无从查证 [8][9]；如果有，再评估接入 Engine A。
   - D3DMetal 不可用时，要在 UI 里**明确提示**用户，不要像 NotProton 的 FEX 构建那样静默回落到其他后端 [39]。
   - 中期跟踪 D3DMetal 会不会出 arm64 版本（CrossOver 说 “DX12 coming soon” [16]，暗示 Apple 可能会给 CodeWeavers 提供 arm64 版，**未证实**）；
   - 长期押注 vkd3d-proton + KosmicKrisp 这条开源路线（见 05 号报告）。
4. **竞品策略**：一周内评估 Highball 的配方和兼容库格式，与维护者沟通数据互通；Cider 的差异化集中在“开源 macOS FEX 后端、应用软件、中文市场、诊断 UX”。

**P1：12 个月内**

5. **许可合规**：DXMT 从 v0.80 之后的版本改为 LGPL（仓库中为 LGPL-2.1）[23][80]。随包分发时要附源码或提供获取方式，并允许替换；GPL-3.0 的 Whisky 或 Highball 代码与 Cider 的许可要事先规划。D3DMetal 的使用目的限制见 [41]，要在 UI 里明确告知用户。
6. **Vulkan 栈**：在 macOS 26+ 上默认用 KosmicKrisp，MoltenVK 1.4.2 作为后备 [24][25]。
7. **系统集成**：`.app` 包装、Games app、Game Mode、原生全屏、MetalFX 插帧开关。
8. **硬件分档**：DXR 和 mesh 相关路径只在 M3+ 开启；M5 Pro/Max 启用神经网络超分的相关选项；8 GB 档调低缓存上限。
9. **兼容性数据库**：做成开放的社区库（兼容 CC0），接收 Highball 和 MacGamingDB 的数据 [37][70]；每条记录都标注芯片、内存、macOS 版本和引擎。

**P2：探索**

10. **VM 兜底**：研究 UTM 的 Triton/Neptune 方案（QEMU LGPL、virglrenderer MIT、DXMT），用来覆盖“需要驱动的中文办公/网银”场景 [41]。这条路线目前仍是实验性的，DX12 路径要依赖用户自备的 D3DMetal [42]。也可以只在 UI 里推荐 UTM 或 Fusion（Fusion 在 Apple silicon 上支持 DX11，且免费 [46][83]）。
11. **云与原生路由**：检测原生版或 GFN 上架情况，引导用户。
12. **Steam Play on macOS**：评估 NotProton 或 macos-steam 的注入方案，注意 AGPL 和 GPL 的传染性 [39]。

## 风险

1. **Rosetta 时间表的不确定性（高）**：Apple 的几个页面说法互相矛盾 [3][75]；“老游戏例外”的机制不明。最坏情况是 macOS 28（2027 秋）起 Wine 进程完全不能再用 Rosetta。
2. **已发行的 D3DMetal 只有 x86_64，且受许可证限制（高）**：GPTK 4 有没有 arm64 版本目前无从查证 [8][9]。如果没有，一旦 Rosetta 退场，DX12 可能在所有免费方案里同时失效 [40][41]。CrossOver 可能拿到 arm64 版 D3DMetal，免费方案拿不到。
3. **macOS 上的 FEX 没有上游支持（高）**：上游 FEX 的 CMake 只接受 Linux 或 Windows（MinGW）宿主，没有 APPLE/Darwin 分支 [76][77]；而 4K 页和 TSO 可能需要 Apple 的受限 entitlement（06 号报告）。开源项目未必拿得到。
4. **竞争与社区观感（中）**：Highball 已经抢先进入同一生态位 [37]；Whisky 当年“寄生 CrossOver”的批评依然存在 [34]。
5. **8 GB 设备比例高（中）**：MacBook Neo 让 8 GB 基数继续扩大 [65][67]，AAA 体验会拉低口碑。Neo 入门价虽然已涨到 $699，教育价仍是 $599 [82]。
6. **原生移植侵蚀头部需求（中）**：Apple 通过 GPTK 4 和 Steam Asset Converter 推动原生移植 [6][8]，Cider 的“AAA 可玩”宣传空间会缩小。
7. **单点维护者（中）**：DXMT（3Shain）和 Gcenx 生态的人手都很少（11 号报告）。
8. **信息可靠性（中）**：
   - CodeWeavers 博客无法直接读取，所以 ARM64 Preview 的 FEX 和 macOS 26.5 细节只有二手来源 [38]；
   - Steam Frame 和 Steam Machine 的发售日期各来源不一致 [29][30]；
   - 部分硬件和 GPU family 数据来自抓取工具的转述；
   - 旧版里有一条 GPTK 4 基准数字（Wukong）核查后查无出处，已删除 [73]。
