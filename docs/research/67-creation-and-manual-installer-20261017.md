# 新瓶子初始化及手动安装交接

2026-10-17，承接66继续原HY1/L6。实现仍在隔离分支，没有恢复主线或更换常用App。此为持续检查点，后续继续特殊快捷方式参数与guest工作目录的实际入口证据。

## 已复现的问题

在全新、无账户的私有瓶子，用受控输出背压暂停初始化阶段：旧版Kill返回0后，创建任务仍运行regedit、winecfg两个后续进程，最终报告created并退出0。失败记录保留在`tests/runtime/exit-status/results/creation-stop-before-coordination.json`。首次观测门没有正确阻塞阶段的超时也保留，没有当作复现成功。

手动EXE/MSI入口原来只读取Spawn.wait的POSIX低8位，也没有接入66的共享活动。新建瓶子到该入口、配方和自动打开之间都有释放活动后再登记的窗口。

## 实现

- BottleStore在独占目录预约后、config公开前提供onReserved回调；BottlePreparation登记停止活动，保留到创建、刷新、安装及打开交接结束。旧create接口保留，四个产品调用点均接入协调器。
- 初始化各阶段及WineRunner最终锁内启动检查共同检查取消；成功完成和Stop依旧原子决定先后。CLI停止解除本命令输出观察，能够退出被终端背压阻塞的进度回调，不重试命令。
- 目录用设备号、inode及目录类型确认归属。失败前尚未启动Wine时不调用依赖config的清理；目录身份改变时保留原物和替代物，不删除不明目录。停止、再次确认和删除使用完整的同一瓶子锁。
- 手动安装器接入与配方相同的打包采集器和完整DWORD判断；MSI仍使用绝对msiexec及明确Windows路径，保持工作目录。普通EXE的256/高位错误不会变成成功；MSI重启要求传给UI，不自动重启。
- 手动安装活动保留到wait及刷新结束，Stop取消后仍回收采集器；初始化与实际运行阶段的GUI Stop均能识别登记。全局安装busy在入口取得，交接成功后才转移释放责任。

收益是关闭停止后复活及错误成功反馈，代价是创建期间保留一个轻量活动、各阶段检查、失败目录身份读回和手动安装的短期采集进程。没有给游戏帧循环增加RPC或采集器。回退应同时撤回协调器、四个创建调用点、手动安装消费及相关GUI Stop交接，不能只删某一检查。

## 复审及修正

一个只读代理进行有界对抗性审查，父代理独立核对调用链：

1. P2：失败停止与删除之间释放锁，另一CLI可能插入启动；已改为同锁完整区间，锁不依赖config且允许killAll同步递归。
2. P2：“新建并安装”未检查全局install busy，可清掉另一任务的标记；已在入口检查/取得，无await的成功交接才转移责任。

最终源码复核在所审链路没有新的P1/P2；它不等于全项目无缺陷或运行验收。

继续HY1特殊快捷方式参数、guest cwd与保存入口的实际证据，保留登录/完整更新/长期和真正游戏会话的独立缺口。HY2原生kernel参考与K2既有工具拒绝仍未闭合，未重试该被拒方案；HY3/HY4/HY5门禁及评级不变。不能把本轮安装可靠性计为三款游戏本体兼容完成。
