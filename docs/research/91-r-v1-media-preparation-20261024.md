# R v1 媒体回归与可取消的首次准备

日期：2026-10-24。承接 88、90；继续原计划 02/ADR-012 的自建引擎媒体主题。Windows、默认引擎、用户瓶子和已下载游戏均未改动。

## 先区分故障与已通过范围

新基线第一次 WMA PE64 在 `CoCreateInstance` 阶段达到原 20 秒 watchdog，CLI 124；PE32 未继续。保留 `runtime-v1.json`。LLDB 12 秒未取得栈，不把它当作互锁证明；外层已确认私有 GUI 退出及两次进程空观察，原诊断 raw 的 running 状态不重写为成功。

独立原生 GStreamer 观察也超过 15 秒，插件 trace 显示持续扫描。允许最多 60 秒的**独立诊断**在 32.14 秒完成；实际最终安装路径的一次显式准备耗时 45.07 秒。它们是环境准备成本，不能据此提高原功能期限或声称零缓存运行通过。

在同一最终安装路径准备后，原期限下实际 Wine PE32/64 各通过：

- 32 次空输出的 `S_FALSE`、状态清零及长度检查。
- 真实 WMA 解码 32768 字节并耗尽；原参考差异指标为 7，原上限 10 保持。
- 释放 DMO 后输入、输出缓冲引用数均为 1。
- EXE、runner、核心、模块、run ID、宿主时钟及 GUI 退出/两次空观察均核对。

这只证明准备后的 WMA/DMO 子集，未证明可听声音、DirectShow、视频像素、完整 MF、游戏或首次全冷会话。`runtime-v1` 失败与 `runtime-v2` 成功分别保留。

## 原始源码身份

`out/engine-r-v1/unpack` 是含早期端口的准备树，不能当未改上游。已从 SHA256 `be19d188…` 的原归档提取四个成员，并与官方固定 commit 的逐文件内容核对。原始 WG sample 为 `3c58ebdf…`，准备版本为 `241e08c2…`；WMA decoder 和两向量与归档一致。新上游 WMA decoder 自身已有 NEED_MORE_INPUT 清状态，因此不把本次成功只归功于 Cider 0007，也不通过覆盖旧树制造“原版”。

## 已采用的产品代码取舍

引擎导入继续只处理字节。带新描述文件的托管媒体包在用户发起执行时增加明确的准备阶段：

1. 登记当前瓶子的活动与取消权限，核对真实计划、配置、门禁及引擎身份。
2. 在瓶子事务锁外取得可取消的引擎锁，校验固定 helper、描述、逐文件 SHA256 和身份。
3. 用显式环境运行随包 `gst-inspect-1.0`；新临时 registry、禁止 fork、总 helper 期限 90 秒及输出上限 1 MiB。后两个进程禁止 registry update，分别核对写出的缓存及最终路径。
4. 缓存就绪记录绑定目录、OS、描述、组件身份和 registry SHA256。复用时仍重新校验组件内容；最终短瓶子/引擎事务只做只读再确认，然后启动 Wine。
5. Stop 取消活动，TERM/KILL 后实际 reap，才释放准备权限。发布后失败保留旧 registry/记录备份及恢复说明，不猜测覆盖可能被其他进程更新的缓存，也不把取消报告为完成。

旧包没有描述文件时保持旧行为。显式专家 GST 路径覆盖保持原行为。普通 GUI/CLI、库启动/重启、新瓶子、配方与手动安装接入准备；停止、wineserver 控制和已有维护操作不触发冷扫描。配方到启动的活动所有权继续传递，普通 GUI 在异步分派前登记活动。CLI `--wait` 仍保留原等待/观察语义，不重放已经提交的请求。

收益是把已观察到的首次扫描从应用内部转成有进度、可停止的依赖阶段。成本是首轮额外约一分钟、缓存及每次启动的校验；本机原生 fixture 首次 54.67 秒，复用含完整校验约 0.61 秒，均不是性能基准。包仍为 32 插件/42 库，新增厂商 inspect helper；新描述库存 76 文件。导入时不执行它。

回退是恢复上一应用构建和没有准备描述的旧包；不需要更改用户存档或游戏下载。当前代码接入已完成，R v1 发布配方和默认采用仍未批准。

## 本轮实际验证

| 范围 | 实际结果 | 边界 |
|---|---|---|
| 原生服务，已批准核心的自有引擎副本 | 首次 prepared；只读 ready；再次 cached | 没复制用户瓶子、没启动 Steam；不是新核心放行 |
| 错误 registry/组件 | 就绪拒绝坏缓存；组件原地改动在 helper 前拒绝；恢复字节但身份改变仍拒绝旧收据 | 不把旧收据当成功凭证 |
| 发布后取消 | 取消抛出；旧 registry/原收据逐字保留在事务备份，存在恢复说明；旧就绪拒绝 | 保留恢复资料，不宣称自动回滚完成 |
| 本机进程与锁的 5 项受影响检查 | 显式环境、超时、取消、输出上限、等待锁时取消均过；被忽略的 TERM 由 KILL/reap 收尾 | 只运行该新组，无额外全量 suite |
| 真 GUI/XPC 创建期间 Stop | 观察到真实 inspect 后 Stop 约 0.79 秒完成，创建非零退出，无 Windows 应用 spawn 或残留 helper | Stop 的 wineserver 控制调用仍存在；不是屏幕点击验收 |
