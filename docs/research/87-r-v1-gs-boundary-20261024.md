# Engine R v1：GS/FS、Fiber 与错误码运行边界

日期：2026-10-24。承接 [86](86-r-v1-profile-renderer-source-20261024.md) 的固定新基线整体 GSBASE 源码审查。这是原引擎迁移的限定运行回归，不代表完整 M1、游戏会话或默认采用。

## 范围与原实现

新基线在 PE 与宿主边界切换整个 GSBASE。旧 Highball0008/0009/0011 的单槽镜像不叠加到这个布局；新 TEB+0x340 已用于 syscall_dispatch。原 v0 补丁和用户引擎均保留。本次没有改 Wine 运行时代码，也没有用空桩替换旧能力。

`tests/runtime/gs-boundary/probe.c` 在已经初始化的私有空瓶中验证：

- 主线程和一个新线程先确认尚未转换，再转换为 Fiber，切换至另一个有效 Fiber 并返回，最后转回普通线程。
- 仅在转换后比较 GetCurrentFiber、直接 GS/FS 读取、TEB 字段与已知 Fiber 指针，再读取 GetFiberData。错误指针先记录失败并退出，不能先解引用。
- 比较 SetLastError/GetLastError、直接 GS/FS 错误码与 TEB 字段；Sleep 后只比较一致性，不承诺未文档化的错误码保留；另核对实际打开缺失文件的错误。
- 在自己的窗口创建回调、可继续的自定义异常处理和排队 APC 内核对线程身份、Fiber 与错误码。回调线程不符时先退出，不在未转换的外来线程调用 Fiber 宏。
- 线程等待和 APC 等待均有限期。所有路径由运行器执行自有 GUI 关闭及进程清理，通过必须具有实际内核退出与至少两次空观察。

这些操作不测宿主 QoS，不写原始 TEB 槽，不触发所有异步信号，不核对物理图形或游戏效果。异常、窗口回调和 APC 的选定路径不能外推为全部跨界已通过。

## 实际结果

PE64 与 PE32 各完成 108 项检查，零失败。实际 EXE、native/两 PE ntdll、运行器、唯一会话标记、时钟和清理回执均已绑定。使用的是新的私有 profile/renderer 组合，原 F27 小时结果不扩大为这个组合的整体通过。

限定负例将探针的原始 Fiber 读数替换为 0x20ff，没有改变真实 TEB 或引擎。两种位宽均在第七项记录错误，退出码 121；没有读取 GetFiberData，没有超时，没有被记成正常通过，清理已确认。这证明选定错误读数的拒绝路径，不是 Wine 或内核故障注入。

回执要求主线程、新线程和外层各自完整检查清单，共 108 项；检查值必须具有正确类型且相等。11 个纯协议变体涵盖缺项、重复、角色错位、布尔值冒充整数、错误结果及完成计数，均被拒绝。纯协议结果与上述四次真实运行分别记录。

初版两处误导缩进被 Werror 拒绝，修正后两位宽编译均零诊断。旧失败构建回执保留，没有作为运行结果。
