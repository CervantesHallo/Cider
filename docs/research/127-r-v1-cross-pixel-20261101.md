# R v1：跨进程真实 Metal 两色读回，屏幕证据另行待验

2026-11-01，UTC+8。接续[126](126-r-v1-cross-reparent-20261101.md)，保留原资源／取消实现，增加私有 Metal 诊断入口。生产者使用真实导出 CAMetalLayer，提交红／蓝 clear 与 texture→shared-buffer blit；实际 command Completed、无错误后逐个比较每帧160×100全部像素，再请求原有取消／释放流程。host与producer是真实不同进程、相反位宽，host仍使用自有childslot。

四阶段分别观察两帧时模型1、取消且原context仍持有时模型0、最终清理后模型0。实际CID、lease/ticket、PID/birth、nonce与序号逐条绑定；HostSAFE、ProducerSAFE之后，显式GPU drain归还命令／drawable／readback／queue并恢复framebufferOnly，最后才销毁原context和RO观察方。未知GPU状态或异常保留资源，不能用进程退出冒充内部安全完成。

读回的代价只用于诊断：临时关闭framebufferOnly才能blit，原值保存并恢复，不改变产品设置；见[Apple framebufferOnly](https://developer.apple.com/documentation/quartzcore/cametallayer/framebufferonly)。实际[waitUntilCompleted](https://developer.apple.com/documentation/metal/mtlcommandbuffer/waituntilcompleted())与[present请求](https://developer.apple.com/documentation/metal/mtlcommandbuffer/present(_:))分别记录，不能代替宿主显示证据。源审发现调用Wine线程未建立autorelease pool会延迟临时对象释放，v2已补render/drain整个调用的pool；最终Native与客户端限定复审均无遗留P1/P2。

首轮屏幕模式实际红帧读回通过，但CUA getApp超时，没有取得截图，也没有写gate或伪造ACK；host在60秒门限失败，子进程最终强制停止，内部清理不标通过，外层GUI/kernel清理和原字节恢复另证。该failed原件保留。新显式`--gpu-only`同时传递给两个进程，保留全部GPU／四握手／SAFE／drain／正常退出要求，仅不等待不可用的截图工具，逐记录标明模式、capture ACK为0。原截图路径和精确64B ready/gate协议仍保留。

GPU首方向的程序实际62／35全通过，但控制器误写宿主期望63而拒绝；保留failed控制器和raw，只以修正判定器重判原数据，没有重跑该方向。随后只补反向。14组有效编译依赖闭包、202项项目输入、双EXE／16PE／2Native／F27、原raw/session及6份GPU批进程清理／原配置DLL字节或缺失恢复／四保护摘要，另以424项检查独立绑定。Native使用NDEBUG；160B-v2 live、128B-v1 pixel、200B-v1 pipe、Unix9／watch2成组。五文件诊断补丁逐字重建，见[源码](../../tests/graphics/cross-pixel/)和[证据](evidence/r-v1-cross-pixel-20261101.json)。
