# Windows CLI 限时执行器：本机实现与验证（2026-10-11）

接续 plan/14 的 Windows 主力机预算。公网入口没有新配置证据，本轮没有重复探测、操作 Windows 主力机、运行已通过的 Win32 基线或触发 Actions。HY2 原生 kernel 环境、HY3 许可闭环和游戏门禁保持原状态。

## 已实现与取舍

新增 `Tools/windows-task-runner`，仅控制本次普通 CLI 任务：使用 Windows Job Object 记录进程归属、在创建时绑定，再恢复挂起的主线程；普通子进程在父进程退出后仍计入任务。未启用 breakaway，仅继承明确列出的标准输出/错误与 NUL 输入句柄。Windows 的 Job 行为与限制见[微软说明](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)，创建属性以[微软文档源码](https://github.com/MicrosoftDocs/sdk-api/blob/docs/sdk-api-src/content/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute.md)为准。

收益：将“SSH 返回了”与“本次进程已经结束”分开处理；本机截止时间不依赖远端连接持续存活。代价：新增两个普通控制台程序及原生构建/部署验收；不是内核 API 修复，不控制服务/WMI/已有 VM 管理器/另一 RDP 会话启动的活动。

每次接受已有账本预约 ID 与10–600秒，保留最后5秒清理；全部预约必须容纳于09:00–17:00 UTC+8。常规轮询处理超时、STOP及窗口结束；独立监控线程在完整截止时间强制终止本次 Job 与自身，覆盖主线程阻塞。只有成功查询到本次 Job 活跃进程数为零，才写确认清理；硬终止只留下未确认部分回执，不伪造成功。JSON 刷新后通过改名发布，已有完整或部分回执均拒绝覆盖。

独立监控使用[本进程强制终止](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-terminateprocess)，避免把 DLL 清理回调当作可靠的超时退出通道。系统 I/O 取消或调度延迟仍须原生实测，不能宣称已经取得硬实时保证。

回退：本轮没有部署到 Windows；撤销新工具与本机实验即可。累计额度仍由已有持久账本控制，执行器不能自己授权增加额度。回执计时覆盖到子进程清理、未包含最后文件发布和传输；未来控制器还必须测量完整操作、确认执行器返回并核对新鲜回执，不能直接拿此时间冒充全部 Windows 机时。

控制器还须先扣掉该预约中SSH/传输/启动已用时间，保留发布/回传余量，再传递剩余的执行限额；不能每个远程命令重新从整个预约秒数计时。剩余不足10秒不启动新的子任务。该控制器尚未整合，不能仅靠本机夹具通过启用无人值守执行。

## 对抗性自审

- 创建后再加入 Job 存在进程归属空窗；已改用 `PROC_THREAD_ATTRIBUTE_JOB_LIST`，没有晚加入的降级路径，并在恢复前验证真实归属。
- 主线程轮询不能覆盖主线程自身卡住；已增加独立截止线程。故障注入通过独立编译的 deadline fixture，生产程序没有运行时关闭/卡住开关。
- 父进程退出0不代表子树退出；按 Job 计数等待，非零主进程、超时和清理结果分别保留。
- 初始部分回执不能证明任务没有启动；`child_started`为null，不能凭旧的false免除清理。完整回执才记录实际启动状态。
- 输入保留空参数、空格、嵌入引号、末尾反斜杠与Unicode。直接执行EXE，不自动插入shell。若调用方明确选择shell，其语法由调用方承担，不能拼接不可信命令文本。
- 写入限固定本地盘；可读的 EWDK ISO允许作为EXE来源。拒绝网络/设备路径、额外流与已观察到的重解析点。此工具不是对抗恶意同账户进程替换目录的沙箱。
- Job关闭策略只覆盖归入本次 Job 的活动，不推广到外部服务、VM或另一屏幕会话。Windows原生嵌套Job、突然结束执行器、时间窗边界、回执 I/O 故障均尚待验收。

## 本机验证

GCC15.2 x86_64 mingw交叉构建以 C17、Wall/Wextra/Werror/Wconversion/Wsign-conversion 成功；VS2022工程XML及本机验证驱动Python语法通过。首次交叉构建暴露`-municode`已定义UNICODE造成重复定义，源文件已改为条件定义；不是原生MSVC构建证据。

复用先前独立新建的、无账户 Win32 Reference 实验瓶子及r2引擎，仅运行新的合成进程夹具。不是复制用户前缀或重跑权限基线。最终同一版执行器的9项检查均通过：

| 检查 | 本机观察 |
|---|---|
| 参数编码 | 空值、空格、引号、末尾反斜杠、中文均逐码元一致 |
| 旧回执 | 拒绝执行，旧文件不变，合成STOP未创建 |
| 非零退出 | 主进程37，执行器失败，清理确认分别记录 |
| 普通超时 | 保留清理余量后结束，确认本次进程数为零 |
| 父进程先退出 | 主进程0、Job累计2个进程；子进程仍受截止时间管理 |
| breakaway | 合成逃离请求被拒绝，没有第二个进程 |
| STOP | 本次进程终止，完整回执为stopped |
| 不足10秒 | 启动前拒绝，无子进程或回执 |
| 主线程阻塞 | 独立线程到完整10秒截止时结束任务；没有完整成功回执，部分回执保持未确认 |

最后一项在Wine/Unix侧看到ERROR_TIMEOUT的低8位退出状态180；不能把它记成Windows原生返回180。专用实验瓶子已停止，并核对无对应残留进程。[原始字段与源/产物摘要](evidence/windows-task-runner-local-validation-20261011.json)

## 余下验收

Windows预算仍为准备32分钟、测试60分钟，无pending。本机上述结果只证明指定Cider r2环境，不替代Windows原生构建、SSH嵌套Job、失联/强制关闭、窗口边界和磁盘失败验证；执行器尚未在主力机部署，无人值守远程执行仍未启用。接入处等待原有Windows代理名称/TUN设置交接，不重复索取。Native验证闭合后才能接到预算/传输控制器，再继续原HY阶段。
