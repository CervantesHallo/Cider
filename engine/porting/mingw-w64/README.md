# 私有 CRT 生命周期候选

固定输入为 MinGW-w64 v14.0.0，源码归档 SHA256：`6eaf921d9eb987d3820b364ea9775bc19b965ec81490b6fdd716526c28e1995c`。

`0001` 在调用 TLS 析构回调前清除槽值，避免后续 C++ 静态析构重新取得已释放的 emutls 存储。只在清除成功后调用析构；没有把失败报告成清理成功。失败恢复、多轮重新设置 TLS 与完整 CRT 一致性仍需独立验收。

本次只在 `out` 克隆的 `libmingw32.a` 中替换一个 `tlsthrd` 对象；两架构其余各 30 个成员逐字不变。未修改用户安装的编译器、系统库或 Wine 核心。相同 C++ DLL 源和最终公开探针下，旧 CRT 的 PE32/PE64 卸载均观察到访问异常，新候选均正常卸载；完整证据及边界见[研究 94](../../../docs/research/94-r-v1-gpu-teardown-20261025.md)。补丁头的 pending 是创建时状态，以该研究记录为准。

这是非默认依赖候选；不能单凭最小 DLL 的结果宣称所有 TLS 析构、Windows 契约或游戏通过。
